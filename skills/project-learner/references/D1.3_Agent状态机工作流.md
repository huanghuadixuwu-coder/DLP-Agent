# D1.3 Agent 状态机工作流

## 🎯 知识点概述

LangGraph 实现的多节点 Agent 工作流，通过状态流转实现复杂的 Agent 行为。

## 🔍 核心概念

### AgentState 状态定义
```python
class AgentState(TypedDict, total=False):
    request_id: str
    session_id: str
    problem_id: str
    question: str
    selected_mode: str
    mode_used: str
    query_type: str
    execution_stage: str
    requires_confirmation: bool
    approved_plan: bool
    is_follow_up: bool
    recent_turns: list[dict[str, Any]]
    recent_turns_block: str
    knowledge_docs: list[Any]
    memory_docs: list[Any]
    retrieved_docs: list[Any]
    context_text: str
    retrieval_preview: dict[str, Any]
    plan_steps: str
    # ... 其他字段
```

### 工作流节点
1. **react_reason** - React 模式推理
2. **plan_task** - 任务规划
3. **pause_for_confirmation** - 暂停确认
4. **execute_plan** - 执行计划
5. **reflect_answer** - 答案反思
6. **finalize_response** - 响应完成

## 🚀 工作流程分析

### 模式选择
- **react_reason**: 直接推理模式
- **plan_execute**: 规划执行模式
- **reflection**: 反思模式

### 路由逻辑
```python
def route_after_mode(state: AgentState) -> Literal["react_reason", "plan_task", "reflect_first"]:
    if state["mode_used"] == "plan_execute":
        return "plan_task"
    if state["mode_used"] == "reflection":
        return "reflect_first"
    return "react_reason"

def route_after_plan(state: AgentState) -> Literal["pause_for_confirmation", "execute_plan"]:
    if state.get("execution_stage") == "preview" and not state.get("approved_plan", False):
        return "pause_for_confirmation"
    return "execute_plan"
```

### 问题2: 状态管理模式

### 问题3: 模式切换逻辑

### 问题5: 性能监控

## 💡 重点分析

### 1. 状态流转优势
- **可追溯性**: 每个状态变化都有完整记录
- **并行化**: 不同节点可以并行处理
- **模块化**: 每个节点职责单一

### 2. 集中式状态管理
- **状态一致性**: 避免分布式状态同步问题
- **调试友好**: 状态集中便于调试
- **扩展性强**: 易于添加新状态字段

### 3. 模式设计哲学
- **react_reason**: 适合简单直接的问题
- **plan_execute**: 适合复杂任务分解
- **reflection**: 需要自我改进的场景
