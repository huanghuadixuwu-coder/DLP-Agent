# Mail Agent UI Contract

This file extends `spec/AGENT_UI_SPEC.md` for Mail Agent V2.

## UI Principles

- The main chat answer is generated by the LLM renderer from observations.
- UI panels show state, evidence, provenance, and next actions.
- UI must not offer a send button that bypasses confirmation, DLP, approval, or task state.
- Debug information must remain separated from the user-facing answer.

## Surface Separation

### `8511`: User Workspace

The user workspace contains:

- Main Agent conversation
- Inbox and thread views
- Draft review
- Explicit send confirmation
- Outbound safety confirmation for the sender's own tasks
- Simplified task progress
- Renderer-generated recovery guidance

When DLP detects medium risk, the sender can revise, cancel, or perform an audited second confirmation on `8511`.

When DLP detects high risk, the sender sees a waiting-for-governance-review state. High-risk exception approval is not available on `8511`.

### `8512`: Governance Console

The governance console contains:

- High-risk exception approval and rejection actions
- Governance task timeline
- Audit events
- Provider health
- Queue health
- Failure recovery observations
- DLQ and safe replay
- Mail Harness results
- Trace, latency, token, and cost diagnostics

Prometheus remains the metrics backend. Grafana is deferred.

## Required User Workspace Panels

### Inbox / Thread

- Mailbox sync status
- Recent threads
- Unread count
- Important/risk hints
- Thread detail with sanitized body view

### Draft Review

- Recipients
- Subject
- Body preview
- Attachments
- Source policy
- Missing fields
- Confirmation state

### Simplified Task Progress

- Draft ready
- Waiting for confirmation
- DLP processing
- Waiting for sender safety confirmation
- Waiting for governance review
- Sending
- Sent
- Failed with renderer-generated guidance

## Required Governance Console Panels

### Governance Timeline

- Draft created
- Confirmation requested
- User confirmed
- DLP queued
- DLP result
- Approval state
- Send queued
- Send result
- Failure recovery or DLQ state

### Provider Health

- Provider type
- Auth status
- Last sync
- Last provider error
- Queue backlog

### Recovery and Diagnostics

- Failure observations
- Retry status
- DLQ entry
- Safe replay action
- Tool observations
- Trace evaluation
- Latency, tokens, and cost

## Display Rules

- Raw HTML is never rendered directly.
- Raw sensitive body is not shown in debug panels unless the user has permission and the panel is explicitly expanded.
- Source policy should be visible near draft review.
- If a provider capability is missing, UI shows provider boundary state from observation.
- Sender safety confirmation for medium-risk tasks exists on `8511`.
- High-risk exception approval and rejection controls exist only on `8512`.
- Critical-risk tasks are blocked by default and do not expose a normal approval action.
- Raw debug and operational metrics do not appear on `8511`.
