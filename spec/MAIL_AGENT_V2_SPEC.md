Status: boundary locked

This is the short entrypoint for Mail Agent V2. Detailed design is split under `spec/mail-agent/` so each reader can open only the layer they need.

## Locked Direction

Mail Agent V2 focuses on the mail domain:

- Search, read, summarize, reply, forward, draft, confirm, DLP, approval, and send.
- Normalize mail thread, label, mailbox, attachment, body source, HTML/plain text, and provider metadata.
- Keep all user-visible answer, clarification, and draft preview generated by the LLM renderer from typed observations.
- Treat Docs, Drive, Sheets, Slides, and Forms as future Workspace/Document domain agents called by the Supervisor through DAG, not as Mail Agent internals.
- Treat Mail Harness as first-phase core work, not a late test add-on.

## Non-Negotiables

- Docker is the only valid verification environment.
- Code owns state, constraints, permissions, source boundaries, tool calls, and observations.
- LLM renderer owns normal user-facing wording.
- Side-effectful actions require permission, confirmation, DLP where applicable, and auditable task state.
- Bad-case fixes must improve structured state or tool observations, not hard-code a visible answer.

## Current Stage

The project already has a working mail/DLP/SMTP chain. V2 should consolidate it into a durable Mail Domain Agent with persistent drafts, provider abstraction, replayable harness cases, and clearer UI state.
