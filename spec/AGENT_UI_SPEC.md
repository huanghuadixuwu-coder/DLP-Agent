# Agent UI Spec

Status: boundary locked
Date: 2026-05-30

This file defines the UI contract for the enterprise Agent app. Domain-specific UI details live in their own files, such as `spec/mail-agent/UI_CONTRACT.md`.

## UI Responsibility

The UI displays:

- Conversation answer generated by the renderer.
- Typed observations.
- Pending confirmations.
- Draft review state.
- Governance and task timelines.
- Provider health.
- Debug and trace details.

The UI does not:

- Compose final business wording.
- Bypass confirmation, DLP, approval, or task state.
- Render raw unsafe HTML.
- Hide provider boundary failures as successful actions.

## UI Surfaces

### User Workspace: `http://localhost:8511/`

The user workspace is for normal employees.

It includes:

- Agent conversation
- Inbox and thread views
- Draft preview and patch flow
- Explicit send confirmation
- Outbound safety confirmation for the sender's own tasks
- Simplified task progress
- Renderer-generated failure guidance

It excludes:

- High-risk exception approval and rejection actions
- Raw tool calls and trace JSON
- Token and cost diagnostics
- Queue depth
- Fault injection controls
- Dead letter queue replay
- Prometheus raw snapshots

### Governance Console: `http://localhost:8512/`

The governance console is for approvers, administrators, and technical operators.

It includes:

- High-risk exception approval and rejection
- Task timeline and audit trail
- Provider health
- Queue health
- Failure recovery observations
- Dead letter queue and safe replay
- Mail Harness execution results
- Trace diagnostics
- Latency, token, and cost diagnostics

### Metrics Backend

Prometheus remains the metrics backend. Grafana is deferred.

## Layout Principles

### Main Chat

The main chat area shows user messages and renderer-generated assistant responses.

### Review Panels

Review panels show structured state:

- recipients
- subject
- body preview
- source policy
- missing fields
- confirmation status
- DLP risk
- approval status

### Debug Panels

Debug panels are expandable and separated from normal user output.

They may show:

- tool calls
- observations
- trace evaluation
- token and latency metrics
- task state
- queue health

## Safety Rules

- Send actions require confirmation state from backend.
- The `8511` user workspace includes an `outbound safety confirmation` panel for the sender's own tasks.
- Medium-risk tasks can be revised, cancelled, or confirmed again by the sender on `8511`; the confirmation is audited.
- High-risk exception approval and rejection actions exist only in the `8512` governance console and require role permission.
- Critical-risk tasks are blocked by default and cannot be released through the normal approval path.
- Raw mail body and attachment body are hidden by default.
- Sanitized HTML can be previewed only after sanitization status is available.
